## 这是什么

在同一个局域网内（家里、办公室、宿舍、机房），把文件从电脑传到手机、手机传到电脑、电脑之间互传。

**不经过任何服务器，走内网直连**，速度跑满你的内网带宽（千兆网络下实测约 **110 MB/s**），比微信、QQ、网盘快几十倍，也没有文件大小和数量的限制。

**架构特点**：一端开服务，另一端只需浏览器。所以接收方不需要安装任何程序 —— 手机、Linux、macOS、黑苹果都能直接用。

```
┌─────────────────┐        局域网直连        ┌─────────────────┐
│   房主端         │  ←──────────────────→   │   访客端         │
│  运行本工具       │      HTTP + SSE         │   只需一个浏览器   │
│  (exe / .sh)     │      不经服务器          │   (无需要装程序)   │
└─────────────────┘                          └─────────────────┘
```

## 快速开始

### 方式一：Windows 用户直接用 exe（推荐）

1. 前往 [**Releases**](../../releases/latest) 下载 `局域网文件传输.exe`
2. 双击运行
3. 程序会自动打开浏览器（地址 `http://127.0.0.1:9000`），控制台显示：
   ```
   ==========================================================
     局域网文件传输  v1.1.0
   ==========================================================
     本机访问    http://127.0.0.1:9000
     局域网访问  http://192.168.1.10:9000
     接收目录    C:\Users\你\Downloads\LANFileTransfer
   ==========================================================
     >>> 房间码：A3F9K2   <<<
   ```
4. 让接收方**连上同一个局域网**，浏览器打开 `http://192.168.1.10:9000`，输入房间码 `A3F9K2`
5. 双方在网页里互相发送文件

> ⚠️ **首次运行 Windows 会弹防火墙询问框，必须勾「专用网络」并点「允许访问」**，否则其他设备连不上。

### 方式二：Linux / macOS / 黑苹果用户

```bash
# 下载启动脚本（或从 Release 下载）
chmod +x 启动-linux-mac.sh
./启动-linux-mac.sh
```

脚本会自动检测并安装依赖（flask / qrcode / pillow / psutil），需要 Python 3.9+。

> macOS 上不要双击 `.sh`（会用文本编辑器打开），要在「终端」里运行。

### 方式三：从源码运行（任意平台）

```bash
git clone https://github.com/chenzhuanxin/lan-file-transfer.git
cd lan-file-transfer
pip install flask qrcode pillow psutil
python run.py
```

加 `--no-browser` 参数可以不自动打开浏览器。

## 核心功能

### 📤 发送文件

- **拖拽**文件或整个文件夹到页面任意位置
- **点按钮选择**文件 / 文件夹（调用系统原生选择框）
- **浏览本机目录**勾选（服务端直接读盘，适合挑一批散落各处的文件）
- 支持多文件批量、整个文件夹递归，**自动保留目录结构**

### 📥 接收文件

- 对方发来的文件自动落到「保存目录」，可在界面随时更改
- 默认目录：`~/Downloads/LANFileTransfer`（跨平台统一）
- 一键在资源管理器 / Finder / 文件管理器里打开保存目录
- 重名文件自动加序号（`报告.pdf` → `报告 (1).pdf`），**不覆盖已有文件**

### 📊 传输监控

- **双向速度**：顶部同时显示上传速度和下载速度（1 秒滑动窗口，实时准确不跳数）
- **每个任务**：进度条、百分比、已传/总量、瞬时速度、剩余时间预估
- **任务管理**：单个取消、一键清理已完成记录

### 🌐 网络信息

- 本机所有网卡与 IP（区分物理网卡/虚拟网卡，自动推荐最优地址）
- 公网出口 IP 探测（多数据源自动降级）
- 局域网设备扫描（ARP 表 + UDP 广播 + TCP 探活）
- 连接地址自动生成二维码，手机扫码即用

## 🔐 房间码与定向传输（公司多人场景）

**默认就是锁着的。** 别人即使知道你的 IP，没有房间码也看不到任何东西、传不了任何文件。

### 三种「凭证」各管一件事

| 凭证 | 举例 | 作用 | 怎么给 |
|---|---|---|---|
| **IP 地址** | `192.168.1.10:9000` | 门牌号 —— 找到你在哪台机器 | 直接说，不是秘密 |
| **房间码** | `A3F9K2` | 钥匙 —— 进门的资格 | **私聊**发给指定的人 |
| **定向锁定** | 点「只收他的」 | 保险栓 —— 锁死只有他能发给我 | 对方连上后手动点 |

> 房间码字符集刻意排除了 `0 O 1 I L` 等易混字符，方便口头告知或手抄。

### 只发给某一个人（完整流程）

场景：你（A）、小张（B）、小李（C）都在同一局域网，你只想发给小张。

1. **你启动程序**，控制台显示房间码 `A3F9K2`（本机浏览器自动登录，不用输码）
2. **私聊**把 `http://192.168.1.10:9000` + `A3F9K2` 发给小张（别发大群）
3. **小张**打开网页、输码、填个称呼"小张"（大小写、短横线、空格都会自动纠正）
4. **你**点「房间成员」→ 看到 `192.168.1.23 小张 在线` → **点「只收他的」**
5. 之后小张发文件正常收；**小李即使偷到房间码上传也会被拒**，提示"本次传输不是发给你的"

### 房间管理（房主专属）

| 操作 | 效果 |
|---|---|
| **更换房间码** | 立即换新码，**所有已连成员强制掉线**，适合房间码泄露时 |
| **关闭外部连接** | 所有成员立即掉线，新人即使有码也进不来，只有本机能用 |
| **踢出成员** | 单个成员令牌立即失效，需重新输码 |
| **取消定向** | 恢复接收所有持码者发来的文件 |

### 防护机制

- 房间码输错 **10 次按 IP 锁定 300 秒**（防暴力猜码），锁定按 IP 隔离，不影响其他人
- 令牌用 `hmac.compare_digest` 比对，**防时序攻击**
- 未认证请求统一返回 `401`，响应中**不泄露房间码**

## 🖥 跨系统支持

**跨系统互传完全可以，但有个关键前提：**

| 角色 | 需要什么 | Windows | Linux | macOS / 黑苹果 |
|---|---|---|---|---|
| **房主端**（开服务） | 运行本工具 | ✅ 直接跑 exe | ✅ 跑 `启动-linux-mac.sh` | ✅ 跑 `启动-linux-mac.sh` |
| **访客端**（收发文件） | **只要浏览器** | ✅ | ✅ | ✅ |

> ⚠️ **exe 不能拿到 Linux/macOS 上运行** —— 它是 Windows PE 格式（实测文件头 `MZ` + `PE\0\0`），Linux 用 ELF、macOS 用 Mach-O，格式互不通用。
> **但访客端根本不需要程序，只要浏览器。** 这是"一端开服务、另一端浏览器访问"架构的关键红利。

**四种组合全都可行**：Windows↔Windows、Windows房主→Linux/Mac访客、Linux/Mac房主→Windows访客、多系统混连一个房间。

详细说明见 [**跨系统使用说明.md**](跨系统使用说明.md)。

## 常见问题

**Q：其他设备连不上怎么办？**

按顺序排查：

1. **确认同一网段** —— 对比两台设备 IP 前三段是否相同（如都是 `192.168.1.x`）
2. **检查防火墙** —— Windows 首次运行要点「允许访问」；Linux 开了 ufw 需 `sudo ufw allow 9000/tcp`；macOS 在「系统设置 → 网络 → 防火墙」允许传入连接
3. **公司网络可能开了 AP 隔离** —— 同网段设备互相不可见；换手机热点试一次即可确认
4. **虚拟网卡干扰** —— VMware、VPN 网卡可能干扰，程序已自动降权，必要时手动选 IP
5. **杀毒软件拦截** —— 360、火绒可能拦，加信任

**Q：能跨网络传吗（不在同一个局域网）？**

不能。本工具走局域网直连、**不经任何服务器** —— 这既是它快的原因，也是它只能在同一内网使用的原因。跨网络传需要中继服务器或 P2P 打洞，是另一个复杂度级别的东西。

**Q：支持多大的文件？**

理论上无上限。传输采用 8MB 分块流式读写，**内存占用恒定**，传 100GB 的文件也不会爆内存。

**Q：杀毒软件报警？**

PyInstaller 打包的 exe 因为会监听端口，容易被 360/火绒误报。这是打包工具的通用问题（未做数字签名），加信任即可。打包时已刻意**不开 UPX 压缩**，正是为了降低误报率。

**Q：接收速度能有多快？**

取决于你的网络：
- 千兆有线 / WiFi 6：约 100 MB/s（1GB 文件约 10 秒）
- 百兆网络 / 老 WiFi：约 10 MB/s
- 实际瓶颈通常是 WiFi 无线速率，不是本程序

**Q：端口 9000 被占用了？**

程序会自动往后找可用端口（9000–9019），启动时看控制台输出的实际地址。

**Q：房间码要记多久？**

程序每次启动都会生成新房间码。想固定，改动 `app/auth.py` 里 `AuthManager(room_code="你的码")` 即可。

**Q：传输记录同事能看到吗？**

看不到。每个连接只看到自己发起的任务和你共享的内容。普通成员看不到房间码，也看不到成员信息。

## 安全设计

| 机制 | 说明 |
|---|---|
| **房间码访问控制** | 6 位码（排除易混字符），未认证一律 401 |
| **暴力猜码防护** | 失败 10 次按 IP 锁定 300 秒，按 IP 隔离 |
| **时序攻击防护** | `hmac.compare_digest` 比对令牌 |
| **定向传输** | 房主可锁定只接收指定 IP 的文件 |
| **容量预检** | 发送前算好总大小和目标盘剩余空间（含 2% 余量），不够直接弹窗 |
| **写满捕获** | 传输途中磁盘被占满也能捕获，不会损坏文件 |
| **SHA256 校验** | 传完自动校验，数据损坏会被发现而不是悄悄存下坏文件 |
| **断点续传** | 大文件传一半断了，重连后从断点继续 |
| **路径清洗** | 阻止 `../` 目录穿越（`../../etc/passwd` 会被拍平进接收目录） |
| **原子落盘** | 先写 `.part` 临时文件，校验通过才改名，不会留半成品 |
| **防覆盖** | 重名文件自动加序号，绝不覆盖已有文件 |

> **可信度说明**：本工具为**明文 HTTP**，仅限内网使用，不含加密层。数据纯点对点，不经过任何外部服务器。无外联行为（仅启动时可选查询公网 IP，可关闭）。

## 技术实现

### 关键技术决策

| 决策 | 原因 |
|---|---|
| **Python + Web 界面**（而非原生桌面窗口） | 传输进度条、速度曲线、拖拽上传用 Web 做又快又好；打包后仍是单文件 exe。额外好处：**手机不用装 App** |
| **SSE 而非 WebSocket** | WebSocket 在某些代理环境会被拦；SSE 兼容性更好，且失败时前端自动降级轮询 |
| **自定义流式协议**（而非 multipart） | multipart 拿不到总大小、无法断点续传、大文件占满内存；自研协议才能做到内存恒定 + 断点续传 + 精确进度 |

### 传输协议

- **上传**：`POST /api/upload` + `application/octet-stream`，配 `X-Rel-Path` / `X-File-Size` / `X-File-Sha256` / `X-Offset` 请求头
- **实时进度**：`GET /ws`（SSE），前端 `EventSource` 订阅，失败自动降级为轮询
- **8MB 分块**流式读写，内存恒定
- **1 秒滑动窗口**速度计量

### 跨平台适配

| 功能 | Windows | Linux | macOS |
|---|---|---|---|
| 磁盘分区枚举 | `GetLogicalDrives` 位掩码 | `/` + `/media`、`/mnt`、`/run/media` | `/` + `/Volumes/*` |
| ARP 邻居表 | `arp -a`（GBK） | `ip neigh`（UTF-8） | `arp -a` |
| 打开接收目录 | `os.startfile` | `xdg-open` | `open` |
| 默认下载目录 | `~/Downloads` | `~/Downloads` | `~/Downloads` |

前端（浏览器界面）**100% 平台中立**，无任何 Windows 专有逻辑。

## 从源码构建

```bash
# 安装依赖
pip install flask qrcode pillow psutil pyinstaller

# 打包单文件 exe（Windows）
pyinstaller build.spec

# 产物在 dist/局域网文件传输.exe
```

**打包要点**：
- `static/` 必须一起打包（否则界面 404）
- `console=True` 保留控制台（显示房间码、连接地址、二维码）
- `upx=False` **不开 UPX 压缩** —— 杀软对 UPX 压缩的 exe 误报率极高

**其他平台**：PyInstaller **不能跨系统打包**，Linux/macOS 需在对应系统上重新打包。
